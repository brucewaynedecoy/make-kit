# Phase 1: Shared Rule Links in PRDs 01 and 05 to 09

## Purpose

This phase changes the Make Blueprint PRDs that state shared rules: 01, 05, 06, 07, 08 and 09. Each shared rule gets one owner in the root PRD set. The Make Blueprint text keeps what Make Blueprint itself needs and points to the root owner for the rest. The [overview](00-overview.md) holds the coordinate, the owner questions and the worker plan.

## Rules for This Phase

- A `link-only` row means that the root rule is correct and the Make Blueprint text agrees with it. Replace the restated rule with one short sentence and a link to the root section. Keep the Make Blueprint detail that the row names.
- An `update-existing` row means that the Make Blueprint text differs from a root rule or a root decision. Change the current normative text so that it agrees with the root owner, and link that owner.
- A `none` row means that the text is Make Blueprint's own, or that it waits for an owner answer. Do not change it in this phase.
- A row with a gate waits for the answer to that owner question in the [overview](00-overview.md#owner-questions). The decision in the row is the decision for the recommended answer. When the owner picks the other option, the row text and the overview say what changes instead.
- Write each root link from `docs/prd/` with four `../` steps, for example `../../../../docs/prd/05-kit-conventions.md#mcp-server`. The links in this file have five steps, because this file is one folder deeper.
- Change no heading text in PRDs 01 and 05 to 09. Root PRDs, register items and backlog tasks link to these headings.
- Keep the front matter of each PRD. Add one line to the `## Source Anchors` list of each changed PRD: `docs/plans/2026-11-01-w1-r2-shared-rules-links/00-overview.md`.
- Keep the `<user-home>/...` code anchors as they are. This plan does not change code anchors (see [Out of Scope](00-overview.md#out-of-scope)).
- Write in ASD-STE100 Simplified Technical English. Use no semantic line breaks.
